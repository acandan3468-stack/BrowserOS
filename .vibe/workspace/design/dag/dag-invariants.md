# DAG Engine Invariants — browseros-dag

**Status:** DESIGN  
**Date:** 2026-07-13  

---

## 1. Structural Invariants

### DAG-INV-001: DAG is acyclic
**Rule:** `DagEngine::add_edge()` detects cycles via Tarjan's algorithm.  
**Enforcement:** Returns `DagError::CycleDetected` if edge creates a cycle.  
**Checked:** At edge addition and at `execute()`.

### DAG-INV-002: Every node in an edge exists
**Rule:** Both `from` and `to` nodes in `add_edge()` must be registered.  
**Enforcement:** Returns `DagError::NodeNotFound` if either is missing.  
**Checked:** At edge addition.

### DAG-INV-003: Entry nodes have in-degree 0
**Rule:** Entry nodes passed to `execute()` must have no dependencies.  
**Enforcement:** Returns `DagError::NodeNotFound` if entry node is not a root.  
**Checked:** At execution start.

### DAG-INV-004: No duplicate node IDs
**Rule:** Each `NodeId` is unique within a `DagEngine`.  
**Enforcement:** Returns `DagError::NodeAlreadyExists` on duplicate.  
**Checked:** At `register_node()`.

### DAG-INV-005: Execution IDs are unique
**Rule:** Each `execute()` call gets a unique `ExecutionId` (UUID v7).  
**Enforcement:** Generated by `ExecutionId::new()`.  
**Checked:** At execution start.

## 2. Execution Invariants

### DAG-INV-006: Nodes execute in topological order
**Rule:** If `A → B` (A must run before B), then B waits for A to complete.  
**Enforcement:** Topological sort before execution. Layer-by-layer execution.  
**Checked:** At each layer transition.

### DAG-INV-007: Independent nodes execute in parallel
**Rule:** Nodes in the same topological layer (no dependency between them) run concurrently.  
**Enforcement:** Thread pool dispatches all layer nodes simultaneously.  
**Checked:** At layer execution.

### DAG-INV-008: All upstream nodes must complete before downstream starts
**Rule:** A node with multiple dependencies waits for ALL to complete.  
**Enforcement:** Layer advancement waits for all nodes in current layer.  
**Checked:** At layer completion.

### DAG-INV-009: Single node executes at most once per DAG execution
**Rule:** No node runs twice in a single `execute()` call (retries are on the same node, not re-execution).  
**Enforcement:** Node state transitions Pending → Running → (Completed|Failed). No reset.  
**Checked:** At node start.

### DAG-INV-010: Upstream failure skips downstream
**Rule:** If a node fails permanently, all downstream nodes transition to Skipped.  
**Enforcement:** On permanent failure, mark all transitive dependents as Skipped.  
**Checked:** After node failure.

## 3. Retry Invariants

### DAG-INV-011: Retry count does not exceed max_retries
**Rule:** Nodes stop retrying after `max_retries` attempts.  
**Enforcement:** Counter incremented per attempt; checked before each retry.  
**Checked:** Before each retry attempt.

### DAG-INV-012: Retry delay respects RetryPolicy
**Rule:** Delay between retries follows `RetryPolicy::next_delay(attempt)`.  
**Enforcement:** Uses `Scheduler::schedule_after()` for delay.  
**Checked:** Before scheduling retry.

### DAG-INV-013: Only transient errors trigger retry
**Rule:** Non-transient errors (Permanent, Configuration, Internal) skip retry.  
**Enforcement:** Check `error.is_retryable()` or classify error kind.  
**Checked:** After node execution failure.

### DAG-INV-014: Maximum retry duration is bounded
**Rule:** Total time spent retrying a single node does not exceed `timeout`.  
**Enforcement:** Cumulative attempt time checked before each retry.  
**Checked:** Before each retry attempt.

## 4. Cancellation Invariants

### DAG-INV-015: Cancellation is cooperative
**Rule:** `cancel()` sets a flag; currently executing nodes must check it.  
**Enforcement:** Nodes check `CancellationToken::is_cancelled()` between retries.  
**Checked:** At retry boundaries.

### DAG-INV-016: Cancelled execution cannot be resumed
**Rule:** Once cancelled, a DAG execution is terminal.  
**Enforcement:** `DagExecutionState::Cancelled` is final. No transition out.  
**Checked:** At state transitions.

### DAG-INV-017: Cancellation emits event
**Rule:** `cancel()` emits `DagExecutionCancelled` on EventBus.  
**Enforcement:** Events module publishes on cancel.  
**Checked:** At cancellation.

## 5. Concurrency Invariants

### DAG-INV-018: DagEngine is Send + Sync
**Rule:** All public API methods are safe to call from any thread.  
**Enforcement:** `Arc`-based interior mutability, `RwLock` for state, `Mutex` for thread pool.  
**Checked:** At compile time via trait bounds.

### DAG-INV-019: Graph mutations are exclusive
**Rule:** `register_node()` and `add_edge()` cannot run concurrently with `execute()` for the same DAG.  
**Enforcement:** Execution sets a read lock; mutations require write lock.  
**Checked:** At lock acquisition.

### DAG-INV-020: Node execution is isolated
**Rule:** Node closures run in their own thread. No shared state between nodes except through DAG result.  
**Enforcement:** Each node receives only its inputs. No `Arc` sharing of mutable state.  
**Checked:** By design.

## 6. Observability Invariants

### DAG-INV-021: Every node lifecycle change emits an event
**Rule:** Started, completed, failed, retrying, and skipped all produce EventBus events.  
**Enforcement:** Executor calls `EventBus::publish()` at each transition.  
**Checked:** At each state transition.

### DAG-INV-022: Every execution produces metrics
**Rule:** Counters for `dag.nodes.started`, `dag.nodes.completed`, `dag.nodes.failed`, `dag.executions.total`.  
**Enforcement:** Executor increments metrics counters.  
**Checked:** At each state transition.

### DAG-INV-023: Every node execution creates a trace span
**Rule:** `Tracer::span()` wraps each node execution.  
**Enforcement:** Executor creates span before running, drops on completion.  
**Checked:** At node start/completion.

### DAG-INV-024: No unwrap/expect/panic in production code
**Rule:** All error paths use `Result` or proper error types.  
**Enforcement:** CI lint check. Code review.  
**Checked:** Build time + review.

## 7. Error Handling Invariants

### DAG-INV-025: All errors are typed
**Rule:** No stringly-typed errors. All errors return `DagError`.  
**Enforcement:** `DagError` enum covers all failure modes.  
**Checked:** At compile time.

### DAG-INV-026: Errors are never silently swallowed
**Rule:** No `let _ = result`, no `.ok()`, no `.unwrap_or_default()` that loses error context.  
**Enforcement:** Match or `?` propagation.  
**Checked:** Code review.

### DAG-INV-027: External errors are wrapped
**Rule:** Errors from node closures (Fn() -> Result) are wrapped in `DagError::ExecutionFailed`.  
**Enforcement:** Executor catches and wraps.  
**Checked:** At node completion.

---

## 8. Resource Invariants

### DAG-INV-028: Thread pool size is bounded
**Rule:** Maximum concurrent node executions = thread pool size (configurable, default CPU count).  
**Enforcement:** Bounded thread pool with blocking queue.  
**Checked:** At thread pool creation.

### DAG-INV-029: Execution results are bounded in memory
**Rule:** Execution state is cleaned up after result is consumed or after TTL.  
**Enforcement:** `list_executions()` returns retained executions only. Oldest evicted.  
**Checked:** At execution completion.

## 9. Integration Invariants

### DAG-INV-030: No dependency on browser crates
**Rule:** `browseros-dag` depends only on `browseros-types`, `browseros-event-bus`, `browseros-scheduler`.  
**Enforcement:** Verified in Cargo.toml.  
**Checked:** Build time.

### DAG-INV-031: No dependency on tokio
**Rule:** Threading uses `std::thread` only. No async runtime.  
**Enforcement:** Cargo.toml has no tokio dependency.  
**Checked:** Build time.

### DAG-INV-032: EventBus dependency is one-directional
**Rule:** DAG publishes events but does not subscribe to them for operation.  
**Enforcement:** EventBus used only for `publish()`.  
**Checked:** Code review.
